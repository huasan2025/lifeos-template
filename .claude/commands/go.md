恢复上下文，并判断${USER_NAME}今天最该推进什么。这是每天开始工作的单一入口命令。

> 设计：`/go` 同时做两件事——**恢复**（你在哪、还剩什么）+ **判断**（今天最该做的 1-3 件）。
> 早期版本把判断单独拆成 `/today`，实践中和 `/go` 重叠、且很少单独用，v0.2 合并进 `/go`。

## 步骤

1. 读取 `PROGRESS.md`、`90-System/Identity.md`（我是谁 + 当前状态/主问题）、`90-System/Soul.md`（你的人格与工作模式）
2. **读取关联文档**：「还没做的事」里有 📄 标记的，读取以恢复任务上下文（操作手册、踩坑记录、已确认的凭据和方案等）
3. 从 PROGRESS 的「还没做的事」识别当前活跃的 Problem / Project（wikilink 指向 `02-Problems/` `03-Projects/`，多个时取每区块第一个）
4. 按下方格式输出：先恢复状态，再给今天的判断

## 输出格式

## 当前状态
1-2 句话总结进展 + 列出「还没做的事」（不复述已完成项）。

## 今天最该做的 1-3 件
1. ...
2. ...

## 为什么是这几件
- ...（绑到当前 Problem / 接近现金流 / 资产积累）

## 今天不要做
- ...（容易让${USER_NAME}偏离主线的分心项）

## 最小保底动作
如果${USER_NAME}今天状态很差，至少完成这一件：
- ...

最后问：**今天想从哪件开始？**

## 规则
- 不复述已完成事项；不自作主张开始工作，等${USER_NAME}确认方向
- 关联文档是上轮会话用时间换来的结论，**必须读**，不要跳过
- 判断原则：优先真实问题而非自我感动、优先资产积累而非临时忙碌、优先接近现金流的动作
- 如果${USER_NAME}在逃避关键问题、反复重新规划、或被新灵感带偏，**直接指出**
- 你可以挑战${USER_NAME}的判断，但不替${USER_NAME}做最终决定
- 如果 PROGRESS.md 不存在或为空，告诉${USER_NAME}并问想做什么
