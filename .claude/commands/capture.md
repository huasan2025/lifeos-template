从当前对话中提取写作素材，保存为 Process Note。

## 什么时候用

对话中产生了值得写成内容的洞察、转折、框架时。不是每次对话都需要 capture——只在"这次聊出了东西"的时候用。

## 筛选标准

从对话中筛选值得保存的内容：

| 存 | 不存 |
|---|---|
| 认知转变和顿悟时刻 | 文件读取、工具调用过程 |
| 关键争论和纠正（含纠正的原因） | 常规问答 |
| 新提出的框架/模型/公式 | 已写入其他文件的计划细节 |
| 数据驱动的发现和对比 | 重复讨论的内容 |
| 有情绪张力的瞬间（真实的兴奋、挫败、意外） | 操作性的中间步骤 |

## 输出格式

保存到 `03-Projects/<当前项目>/process/{{YYYY-MM-DD}}_{{简短标题}}.md`（"过程即内容"——Process Note 跟项目走）：

```markdown
---

date: {{YYYY-MM-DD}}
status: draft
```

## 规则

- Process Note 是**索引不是原料**，能用双链指向的就不复制原文
- **例外**：对话清除后无处可查的内容必须保留原文——包括原创洞察（新框架、新公式）和**关键对话原话**（谁说了什么、怎么说的）。这些是写作的核心素材
- 总长度不硬限，但遵循**够用就停**：起因和产出尽量精简，把篇幅留给关键转折和对话
- "可写作的价值点"是给 analyze 原子 skill 的输入，按用户价值三问命中数排序
- 不要美化过程，保留真实的转折和纠正——这些往往是最好的写作素材
- **保留对话归属**：标注哪些话是${USER_NAME}说的、哪些是${ASSISTANT_NAME}说的。关键原话尽量保留原文，不要概括成第三人称叙述。人-AI 协作的真实过程本身就是有价值的内容
- 如果某个转折点只涉及一方（比如${USER_NAME}独自发现、或 AI 独立分析），只标注该方即可，不硬凑对话
